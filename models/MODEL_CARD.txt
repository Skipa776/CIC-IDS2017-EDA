================================================================================

Document Version: 2.0
Created: 2026-06-12

Supersedes: v1.0 card for rf_multiclass_attack_classifier.joblib (model no longer shipped)

================================================================================
1. MODEL OVERVIEW
================================================================================

Architecture:       Two-layer LightGBM pipeline served by api/
  Layer 1:          LGBMClassifier (binary: benign vs attack)
                    num_leaves=31, max_depth=6, n_estimators=100, class_weight=balanced
  Layer 2:          LGBMClassifier (14 attack types; invoked only when Layer 1 flags attack)
                    num_leaves=63, max_depth=8, n_estimators=200, class_weight=balanced

Input:              20 "fast features" (see models/feature_columns.json), scaled by
                    models/feature_scaler.joblib (StandardScaler fit on training data only)
Output:             is_attack, attack probability, attack type, MITRE ATT&CK mapping
Inference:          ~0.45 ms total per flow (both layers, single sample)

================================================================================
2. TRAINING DATA
================================================================================

Dataset:            data/processed/cicids2017_clean_v2.parquet (2,519,262 flows)
                    Built by scripts/build_dataset.py from the 8 raw MachineLearningCVE CSVs.
                    v2 cleaning keeps Init_Win_bytes=-1 sentinel rows (v1 dropped 51% of all
                    data), deduplicates exactly, removes contradictory labels, and normalizes
                    the web-attack label encoding. Manifest: reports/dataset_v2_manifest.json

Split:              Stratified 80/20 split FIRST; benign downsampled to 200k in the
                    training portion only. Test set (503,853 flows) keeps the natural
                    prevalence (16.9% attack) within this dataset, not deployment prevalence.

================================================================================
3. HISTORICAL ARTIFACT METRICS AND CURRENT EVALUATION STATUS
================================================================================

Layer 1 random-split scores are archived in model_metadata.json only; they are
excluded from performance claims. Audit found 1,854 test flows with identical
20-input vectors in training, plus extensive shared behavior profiles. Global
label-aware filtering and undocumented training-only feature selection further
limit that evaluation. See reports/leakage_audit.md and reports/leakage_audit.json.

Current primary evaluation: scripts/audit_leakage.py starts from all eight raw
CSV files with feature-only cleaning, retains duplicates/conflicting labels,
groups related input profiles globally and uses validation-frozen thresholds.
It also tests purged held-out blocks from every file. The primary candidate uses
all 71 inputs; the historically selected 20-input subset is a diagnostic.
These controls improve independence under the stated group proxy, but cannot
verify session or future-network independence without additional metadata/data.

STATUS: the served 20-input model is NOT validated on unseen attacks. Its 20 inputs
were chosen from feature importance fit on all data before a split
(notebooks/archive/attack_types.ipynb), so it is kept only as the API artifact.

Raw-derived whole-day tests (71-input candidate, seeds 42/43/44; day boundary is the
separation unit, profiles are no longer purged across days):
  Friday: AP 0.771-0.788; recall 21.6%-43.9%; realized FPR 1.22%-1.31%.
  Wed+Thu: AP 0.219-0.544; recall 1.0%-1.3%; realized FPR 0.71%-1.20%.
  Forward Thursday: AP 0.651-0.762; recall 81.7%-86.1%; realized FPR 0.82%-1.46%.
    This recall rides on one victim-server TCP window value carried by 83% of
    Thursday's web-attack flows (reports/results/explain_2017_B.json); it is an
    artifact, not attack detection.
All thresholds target 1% validation benign FPR, then stay frozen for testing.
The forward-in-time evaluation that supersedes these (all detectors, 2017 and 2018
folds, 5 seeds) is in reports/results/ and notebooks/03-06.

Historical Layer 1 cross-day holdout (v2 parquet, before raw/profile-purge audit):
  test Friday (Bot/PortScan/DDoS unseen):
    AP 0.824  (no-skill 0.358)   Precision 0.678   Recall 0.011
  test Wed+Thu (DoS family/web/Heartbleed unseen):
    AP 0.466  (no-skill 0.197)   Precision 0.176   Recall 0.041
  (precision and recall at the default 0.5 threshold)

  At the default threshold, the model catches only 1-4% of attack flows from
  attack types it never trained on.

  NOTE: Attack labels are tied to capture days. Day holdouts change attack types,
  benign traffic and capture conditions together; they do not isolate these causes.
  AP remains above prevalence on both holdouts, while default-threshold recall fails.
  This is a combined-shift stress test, not an estimate for arbitrary novel attacks.

  Legacy fixed-FPR results in reports/crossday_threshold_analysis.json choose
  thresholds on test labels and are retrospective diagnostics, not deployed results.
  scripts/evaluate_generalization.py reserves a validation day, freezes thresholds,
  compares 20/71-feature candidates and reports realized test FPR and per-family recall.
  Results: reports/generalization_evaluation.json. Candidates do not replace these models.

Layer 2 (multiclass, all true test attacks, bypassing the Layer 1 gate):
  Macro F1:         0.910      Weighted F1: 0.997
  Weakest classes:  Web Attack - XSS (F1 0.51), Web Attack - Brute Force (F1 0.58),
                    Web Attack - Sql Injection (F1 0.67, n=5)
  This is conditional attack identification, not end-to-end gated pipeline performance.

================================================================================
4. LIMITATIONS & INTENDED USE
================================================================================

- Trained and evaluated on a single 2017 lab-generated dataset with documented label
  noise (Engelen et al. 2021). Absolute metrics do not transfer to other networks.
- Random-split metrics are optimistic for novel attacks; see cross-day numbers above.
- Does not transfer to CSE-CIC-IDS2018 (same lab, different network): a Layer 1 model
  trained the same way on all of CIC-IDS2017 has recall 0.004 at a 1% benign alert
  retrospective test-benign budget on 2018 (reports/cross_dataset_2018.md).
- Web-attack identification (Layer 2) is weak; pair with WAF/application logs.
- Ultra-rare classes (Heartbleed n=11, Infiltration n=36, SQLi n=21 in the full data)
  have anecdotal-quality metrics.
- Intended as a research/portfolio system, not a production security control.
- No reliable cross-day generalization has been established. A promotion requires
  prespecified recall/FPR requirements and fresh captures beyond these explored holdouts.
- File/day provenance is available, but no session IDs or timestamps for session-level
  separation or block-based uncertainty. Seed ranges are not population confidence intervals.
